# Learning checklist

Answer without opening the repository files.

- [ ] I can explain image versus container.
- [ ] I can describe what the Docker client and daemon each do.
- [ ] I can explain `127.0.0.1:8080:8080` from left to right.
- [ ] I can identify buildtime and runtime instructions in the Dockerfile.
- [ ] I can explain why `EXPOSE` does not publish a host port.
- [ ] I can explain how the probe resolves the name `web`.
- [ ] I can predict why the probe fails outside the `app` network.
- [ ] I can explain why the evidence file survives helper-container replacement.
- [ ] I can state the difference between `down` and `down --volumes`.
- [ ] I can show where logs, health, networks, mounts, and the runtime user are inspected.
- [ ] I can explain every security setting in `compose.yaml`.
- [ ] I can reproduce one build, runtime, port, and network failure.
- [ ] I can run the full test from a clean clone.
- [ ] I can clean up only this project's resources.

The project is portfolio-ready only when every item can be demonstrated, not merely checked off.
